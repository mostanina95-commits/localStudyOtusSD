# Выбранная архитектура

## Облачное хранилище (Яндекс Диск)
Система позволяет загружать, хранить и работать с пользовательскими данными с возможностью совместного доступа к ним

Пользователи/акторы, которые работают с системой:
1. Пользователь, который загружает или работает с данными и управляет доступом к ним через выделенный интерфейс

## Ключевые сценарии
1. Загрузка, создание, редактирование файлов
2. Поиск и просмотр файлов
3. Скачивание файлов
4. Совместная работа и выдача прав доступа
5. Управление оплатой за услуги, управление тарифами - биллинг
6. Синхронизация данных с устройств (синхронная автозагрузка в реальном режиме времени или асинхронная)
7. Проверка антивирусом

## Масштаб работы
Миллионы пользователей - 20-25млн
Объем пользовательских данных - более 100 Петабайт
RPS - 100-200 тысяч RPS

## 1. Компоненты

1 Интерфейс -> 2 CDN -> 3 Балансировщик -> 4 API Gateway -> 5 Сервисы (микросервисы) -> 6 БД


### 1.Клиентские интерфейсы: 
Веб-версия, мобильное приложение, десктопное приложение, REST API, приложение для ТВ
За что отвечает: Предоставление возможности пользователю работать с сервисами облачного хранилища

### 2.CDN 
За что отвечает: доставка контента/данных с ближайших к пользователю серверов, используется для распределенных систем с большой нагрузкой

### 3. Балансировщик (Load Balancer)
За что отвечает: балансирует нагрузку, распределение трафика между серверами


### 4.API Gateway
За что отвечает: аутентификация, управление потоками данных и маршрутизация запросов между сервисами, агрегация ответов от сервисов

### 5.Сервисы (микросервисы)

#### 5.1 Сервисы работы с файлами (просмотр, загрузка, создание, скачивание, редактирование, удаление)
За что отвечает: работа с файлами в облачном хранилище

#### 5.2 Сервис поиска
За что отвечает: быстрый поиск данных в хранилище

#### 5.3 Сервис управления доступом
За что отвечает: управление правами доступом к файлам

#### 5.4 Сервис безопасности проверки данных (антивирус)
За что отвечает: проверка безопасности загружаемых файлов

#### 5.5 Сервис оплаты (биллинг услуг)
За что отвечает: проведение оплаты и подписки на пользование услугами хранения данных

#### 5.6 Сервис уведомлений
За что отвечает: реагирование на события работы с файлом и передача нотификации клиенту

#### 5.7 Сервис аналитики
За что отвечает: получение событий и статусов над файлами для построения аналитики


### 6. База данных - Хранилище метаданных
За что отвечает: Структурированное хранилище данных для получения ссылок на файлы из объектного хранилища

### 7.База данных - Объектное хранилище данных
За что отвечает: Хранение больших файлов - байты файлов (картинки, видео, документы)

## 2. Потоки данных


1. Пользователь хочет загрузить файл в облачное хранилище с проверкой доступа к возможности загрузки/созданию файла
    1. Пользователь хочет начать загрузку файла, от внешнего интерфейса идет запрос от пользователя к **API Gateway**
    2. **API Gateway** передает запрос на доступ к созданию файла пользователю к **5.3 Сервис управления доступом**
        - доступа нет - ошибка при создании
        - доступ есть, продолжение сценария (далее п.3)
    3. **API Gateway** передает запрос на создание в **5.1 Сервис работы с файлами**
    4. **5.1 Сервис работы с файлами** создает запись в **6. БД - Хранилище метаданных**, получает ссылку на размещение файла
    5. **5.1 Сервис работы с файлами** передает обратно ссылку на создание через **API Gateway** к пользователю
    6. Пользователь получает ссылку по которому можно загрузить файл в **7. БД - Объектное хранилище данных**
    7. В случае неуспешной загрузки:
        - от внешнего интерфейса передается статус с ошибкой к **API Gateway** и далее повторно по сценарию
        - повторная попытка загрузить, запрос к **API Gatewayr**
    8. В случае успешной загрузки:
    - от внешнего интерфейса передается успешный статус к **API Gateway**
    - от **API Gateway** передается статус в **5.1 Сервис работы с файлами**
    9. По факту успешной загрузки **5.1 Сервис работы с файлами** передает данные о файле в **8. БД - Elasticsearch**

2. Пользователь хочет найти и просмотреть файл из облачного хранилища (проверка доступа за рамками процесса)

1. Внешний интерфейс передает запрос на просмотр файла view() в CDN, если данные есть в кэше, то выдаются. если данных нет, то далее п.2
2. Запрос от **CDN** к **API Gateway** за запросом файла
3. **API Gateway** передает запрос на поиск в** 5.2 Сервис поиска**
    - файл найден, в ответ передается ссылка на файл (далее п.4)
    - файл не найден - передается статус поиска в **API Gateway**, далее в **CDN** и во внешний интерфейс с ошибкой поиска
4. **API Gateway** передает запрос на файл view() с ссылкой на файл к 5.1 Сервис работы с файлами
5. **5.1 Сервис работы с файлами** запрашивает данные на ссылку на файл из **6. БД - Хранилище метаданных**, возвращается ссылка на файл, далее передается в **API Gateway**, далее в **CDN** и во внешний интерфейс
6. Пользователь из внешнего интерфейса открывает ссылку и просматривает файл из **7. БД - Объектное хранилище данных**


3. Пользователь хочет оплатить подписку на облачное хранилище
