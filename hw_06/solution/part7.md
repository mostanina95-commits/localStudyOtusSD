# 7. Безопасность
Термины:
- Идентификация – процедура, в результате выполнения которой для субъекта идентификации выявляется его идентификатор, однозначно идентифицирующий этого субъекта в информационной системе
- Аутентификация – это процесс, в котором мы удостоверяемся, что субъект действительно тот, кто он есть
- Авторизация – проверка возможности и прав субъекта, сможет ли он совершить действие или нет
- JWT (JSON Web Token) - 
- RBAC (Role-Based Access Control) - Значение типа строка, содержит данные пользователя и криптографическую подпись. Используется для аутентификации, где права привязаны к ролям, а роли к пользователям
- bcrypt - Алгоритм хеширования (не шифрования) паролей, нельзя расшифровать обратно, что защищает данные от дешифрования при утечке данных
- mTLS - Mutual Transport Layer Security — взаимный TLS. Обе стороны взаимодействия проверяют друг-друга
- TLS (Transport Layer Security) - безопасность транспортного уровня, протокол шифрования данных, передаваемых по сети
- HTTPS - HTTP + TLS
- pgcrypto - PostgreSQL Crypto — криптографическое расширение для PostgreSQL
- PII - Personally Identifiable Information — персональные данные
- SSE - Server-Side Encryption — шифрование на стороне сервера
  
#### Механизм аутентификации/авторизации, шифрование
1. Пользователь проходит аутентификация в интерфейсе системы с вводом логина и пароля, приложение отправляет запрос HTTPS в API GW с входящими для аутентификации данными
2. Получив запрос, API GW передает данные для проверки в Auth Service через gRPC, при этом API GW не хранит данные логина/пароля и секреты.
3. Auth Service проверяет входные данные пользователя в БД, формирует токены JWT (JSON Web Token) для кратковременной аутентификации пользователя и для долгосрочного входа пользователя в систему, чтобы не входить в систему повторно (реализовано для удобства клиента)
4. Формируется ответ клиенту с данными токена доступа. Теперь каждый запрос к системе будет сопровождаться токеном доступа. API Gateway должен проверять JWT самостоятельно
5. Авторизация - API Gateway проверяет доступные права пользователя (RBAC) на запрос к требуемому сервису
6. В случае успешной проверки, передается запрос к сервису с заголовками уникального идентификатора пользователя, ролью, идентификатором запроса, датой запроса.
7. Внутри системы взаимодействие между сервисами происходит с шифрованием данных mTLS. Каждый сервис должен иметь свой   криптографический сертификат
8. Взаимодействие с API Партнеров происходит через API Key и выданные токены доступа

#### Данные для шифрования
1. Персональные чувствительные данные пользователя PII (телефон, почту, ФИО, паспорт, если вводится, номера карт, пароли)
2. Пароли и токены JWT

#### Уточнения
1. В CDN не должны кэшироваться зашифрованные данные - персональные, токены и пароли, каждый раз при аутентификации
2. Обеспечить шифрование и защиту данных для данных на дисках и бэкапах
3. Файлы в S3 также должны быть зашифрованы
4. Пароли никогда не шифруются, а хешируются алгоритмом bcrypt 
5. Пароли от баз данных, ключи JWT и ключи шифрования нельзя хранить в коде, логах или переменных окружения
6. При удалении аккаунта или по запросу пользователя (152-ФЗ) данные должны не просто помечаться как удаленные, а физически стираться из БД и бэкапов
